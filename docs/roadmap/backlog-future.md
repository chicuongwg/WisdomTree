# Future Backlog

## Purpose
- Hold known future work that should not distort the V1 and phase 1.5 implementation plan.

## In Scope
- Deferred features and strategic follow-up items already known during planning.
- Explicit non-V1 items that may influence architecture awareness but not current implementation scope.

## Out of Scope
- Day-to-day bug backlog.
- Detailed milestone decomposition.
- Ideas with no product relevance.

## Decisions
- Future items are recorded here instead of remaining unresolved in primary docs.
- Items in this file are not implied commitments for the first shipping release.
- Future work may refine role boundaries without changing the core two-repository model.

## Dependencies
- Scope boundaries in [`../product/scope-v1.md`](../product/scope-v1.md).
- Roadmap in [`phases-0-1-1.5.md`](./phases-0-1-1.5.md).

## Acceptance Criteria
- Main docs stay decision-complete for V1.
- Deferred items have a stable holding place.
- Future ideas that matter architecturally are visible without polluting current implementation documents.

## Deferred Items
- Explicit split of `Admin/Op` into `Reviewer`, `Curator`, and `Operator`.
- Richer source preview across more file types.
- Mobile or tablet-first optimized experience.
- Wider format handling and better OCR quality support.
- Advanced analytics for knowledge health, source throughput, and editorial productivity.
- More sophisticated conflict resolution and merge assistance.
- Public publishing or external user portals.
- Multi-tenant organization model.
- More advanced workflow automation and external integrations.
